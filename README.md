# 123share 极简快传 · AstrBot 插件

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](<LICENSE>)

用一句中文，让 AstrBot 帮你通过 [123share.cn](https://123share.cn/) 分享、提取**文字和文件**。

支持“帮我分享一下这个文件”“帮我分享一下这个文字”“帮我取一下”等模糊请求；内容没给全时，机器人会继续追问。**不依赖 LLM，不消耗模型 token，不需要站点 API Key。**

> **隐私提醒：分享会把你指定的内容上传到第三方 123share.cn。** 不要分享密码、令牌或敏感文件。站点说明通常保留 2 小时；本插件不控制站点的实际删除、安全性或可用性。

## 功能

- **文字分享 / 取回**：可直接跟正文、引用消息，或使用限时追问。
- **文件分享 / 取回**：接收平台文件附件，提取后以文件附件发回，不仅仅返回下载链接。
- **中文模糊触发**：识别常见开头请求及“帮我把这个文件分享一下”等语序；不是无限制的自然语言语义理解。
- **先发内容，再说分享**：同一用户、同一会话的最近一条内容，默认 120 秒内可显式引用。
- **会话隔离**：追问按“会话 + 发送者”隔离，默认 120 秒超时；可取消。
- **隐私默认值**：默认只开放私聊；群聊可开启，并要求 @ / 唤醒或显式命令。
- **可选阅后即焚**、用户白名单、大小限制、冷却间隔、有限并发和缓存清理。

## 安装

需要 **AstrBot >= 4.16、< 5.0**，插件代码支持 Python 3.10+；具体 Python 版本仍以所安装的 AstrBot 版本要求为准。

在 AstrBot WebUI → **插件** → **从链接安装** 中填写：

```text
https://github.com/VellowK/astrbot_plugin_123share
```

安装完成后启用插件，在插件配置页面按需调整设置。如果平台未自动安装依赖，请在 **AstrBot 所使用的 Python 环境**中执行：

```bash
python -m pip install -r data/plugins/astrbot_plugin_123share/requirements.txt
```

然后重载插件或重启 AstrBot。手动安装时，把整个仓库放入 AstrBot 的 `data/plugins/astrbot_plugin_123share` 目录。

**不需要另行设置唤醒词 `123share`。** 插件通过消息事件直接识别 `/123share` 文本和中文请求，而非要求用户调用 LLM 工具。

## 使用

### 1. 一句话分享文字

```text
你：帮我分享一下这个文字：下午三点开会，记得带电脑。
Bot：文字分享成功，取件码：1234
     https://123share.cn/?code=1234
```

也支持：

```text
分享：这是一段要分享的内容
请帮我上传一下这段文字：第一行
第二行
/123share 分享 hello world
```

取件码 `1234` 仅为文档示例，不是供测试的真实共享内容。

### 2. 分享文件

任选一种：

1. **同条消息附文件**，配文“帮我分享一下这个文件”。
2. **引用文件消息**，再说“帮我分享一下这个文件”。
3. 先发送文件，再在 120 秒内说“帮我分享一下这个文件”。
4. 先说“帮我分享一下”，收到提示后再发送文件。

```text
你：帮我分享一下
Bot：请在 120 秒内发送要分享的文字或文件……
你：[发送 report.pdf 文件附件]
Bot：文件 report.pdf 分享成功，取件码：5678
```

一次默认最多 3 个文件，每个文件单独生成取件码。如果同条消息同时含文件与正文，会分别分享；站点没有“文件 + 文字组合分享”的接口。多项操作不是事务，后续失败不会撤回已成功的分享。

> 应以**文件附件**发送图片、视频等素材；图片消息组件本身不会自动转成文件。引用分享依赖平台提供完整的引用消息链，部分适配器可能只返回摘要，这时请改用“先说分享，再发附件”。

### 3. 取回内容

```text
你：帮我取一下 1234
Bot：文字提取成功。
Bot：下午三点开会，记得带电脑。
```

也可以先提出请求，再提供取件码：

```text
你：帮我取一下
Bot：请在 120 秒内发送一个四位数字取件码或 123share 分享链接。
你：5678
Bot：[发送取回的文件]
```

支持的其他形式：

```text
/123share 取 1234
请帮我提取一下 １２３４
帮我取一下 https://123share.cn/?code=1234
```

取件码必须是**四位数字**；全角数字自动转换。多组不同取件码、其他域名链接、五位数字等不会用于请求接口。单独发四位数字或分享链接，**只有在等候取件码时**才会触发，不会扫描普通聊天猜码。

### 4. 取消、帮助和关闭模糊触发

```text
/123share 帮助
/123share 取消
取消快传
```

追问期间直接发“取消”也可以。取消会退出等待；`/123share 取消` 还会清除最近内容引用，但**不会中断已经开始的网络传输**。

将 `natural_language` 设为 `false` 后，使用显式命令：

```text
/123share 分享 要分享的文字
/123share 分享
/123share 取 1234
/123share 取
```

显式命令仍可开始追问；追问的下一条内容不需要再加命令前缀。

### 5. 群聊

默认不处理群聊。设置 `enable_group=true` 后，可使用：

```text
@机器人 帮我分享一下
[同一用户发送文件，无需再次 @]
```

默认 `group_require_at=true`：自然语言请求需要 @ / AstrBot 唤醒；显式 `/123share` 命令不受此限制。开启追问后，同一发送者的后续消息可不带 @。先发附件再引用“这个文件”的方式，也需要第一条附件满足群聊唤醒规则；否则请引用附件消息，或先请求分享。

**提取结果发回原会话，包括群聊。** 私密内容请私聊取件。开启分享追问后，该用户下一条非指令文字/附件会被视为待分享内容；不再需要分享时请先取消。

## 配置

在插件配置界面调整；完整定义见 [配置结构](<_conf_schema.json>)。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `natural_language` | `true` | 启用中文模糊触发；关闭后使用显式命令 |
| `allowed_users` | `[]` | 发送者 ID 白名单；空列表允许所有用户，公共 bot 建议填写 |
| `enable_group` | `false` | 是否允许群聊 |
| `group_require_at` | `true` | 群聊自然语言请求需要 @ / 唤醒 |
| `burn_after_reading` | `false` | 新分享默认阅后即焚 |
| `followup_timeout` | `120` | 追问有效期，15～600 秒 |
| `recent_timeout` | `120` | 最近一条内容引用有效期，15～600 秒 |
| `max_file_mb` | `100` | 单文件上限，1～100 MiB，不能超过站点限制 |
| `max_files_per_message` | `3` | 单次最多文件数，1～10 |
| `request_timeout` | `120` | 每次网络请求超时，10～600 秒 |
| `cooldown_seconds` | `3` | 同一用户同一会话的操作间隔，0～60 秒 |
| `file_retention_minutes` | `30` | 本地传输缓存保留时间，5～120 分钟 |
| `download_hosts` | `[]` | 站点额外文件下载主机名，默认仅允许 `123share.cn` |
| `allow_private_downloads` | `false` | 允许内网连接，高风险，仅可信自建适配器按需启用 |

文本限制按站点的 JavaScript 字符计数规则执行：**最多 20000 个 UTF-16 单元**，部分 emoji 占两个单元。

文件缓存位于 AstrBot 数据目录下的 `plugin_data/astrbot_plugin_123share/cache`。只清理插件生成的传输目录，不删除平台原始附件。插件运行时每分钟清理过期缓存；重启后首次处理消息时恢复清理。为兼容平台延迟读取，发送后不会立刻删除文件。卸载插件不会主动销毁尚未到期的缓存，如有敏感数据请管理员手动清理。

## 安全和限制

- 非官方插件，使用站点前端公开调用的接口；**没有稳定性承诺**。站点接口、限额或行为变更后可能需要升级插件。
- 仅在用户主动请求时上传；不调用语言模型，不在日志中记录正文、取件码或完整异常详情。最近内容和追问保存在内存中，过期或插件卸载后清除。
- 最多同时执行 3 项传输；每个会话/发送者不允许重入；交互状态最多 256 组。冷却、大小、数量限制不能替代站点自身风控，请勿滥用。
- 默认阻止本机、私网、链路本地等非公网下载地址，连接时校验 DNS 解析结果；不自动跟随 HTTP 重定向。不把用户提供的本地路径当成附件读取。
- 部分自建 OneBot 等适配器返回内网 HTTP 文件地址，默认会被阻止。仅信任用户和适配器时开启 `allow_private_downloads`，并建议设置白名单；该选项解除连接的私网限制，存在 SSRF 风险。需要身份认证或重定向才能访问的附件 URL 可能无法使用。
- 取件会遵循站点的阅后即焚行为；不自动重试，包括禁用 aiohttp 的断线 GET 重试。**网络中断或平台发送失败也可能导致内容已被远端销毁**。文件已下载但发送失败时，本地临时缓存按保留时间存在，管理员可尝试恢复，不保证远端可重新提取。
- 平台必须支持 `File` 消息组件的接收、解析与发送；平台文件大小/消息频率限制可能比站点更严格。长文本按 1500 字符分条发送。
- 当前测试覆盖协议与交互逻辑，不代表在所有 AstrBot 平台适配器上完成端到端验证。

## 开发与验证

依赖定义在 [requirements](<requirements.txt>)；不需要运行 AstrBot 即可执行使用 API 替身的单元测试：

```bash
python -m pip install -r requirements.txt ruff
python -m unittest discover -s tests -v
python -m ruff check .
python -m ruff format --check .
```

目前包含 **44 项单元测试**，覆盖中文意图解析、四位码与链接解析、HTTP 协议、multipart、大小限制、DNS/私网拦截、重定向拦截、断线不重试、追问/超时/取消、会话隔离、群聊唤醒、引用和最近内容、缓存清理等。当前仓库未启用 GitHub Actions，可在本地或自己的 CI 中执行上述命令。

手动真实站点回环测试：

```bash
python -m tools.live_check --confirm
```

[回环测试脚本](<tools/live_check.py>) 会上传一小段随机测试文字和一个微型文本文件，开启阅后即焚，只读取**本次自己创建的取件码**，并核对文件 SHA-256；不会遍历或读取他人的分享。不加入 CI，避免自动消耗站点资源。开发过程中该真实站点文字与文件回环已通过；尚未进行真实聊天平台联调。

## 协议说明与致谢

感谢 [123share 极简快传](https://123share.cn/) 提供服务。本项目使用其网页前端公开使用的三个接口：

- `POST /api/share/text`：JSON `text`、`burn`。
- `POST /api/share/file`：multipart `file`、`burn`。
- `GET /api/get/{code}`：读取文字，或取得文件元数据及下载地址。

不包含或复制站点前端代码，也不代表与该站点存在官方合作关系。AstrBot 开发约定参考 [AstrBot 官方插件开发文档](https://docs.astrbot.app/dev/star/plugin-new.html)。
